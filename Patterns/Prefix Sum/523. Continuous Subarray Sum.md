# 523. Continuous Subarray Sum

**Difficulty:** Medium

## Problem Statement

Given an integer array `nums` and an integer `k`, return `true` if `nums` has a **continuous subarray** of size **at least 2** whose elements sum up to a multiple of `k`.

A multiple of `k` is any number `n * k` where `n` is an integer.

---

## Examples

### Example 1

```text
Input:
nums = [23,2,4,6,7], k = 6

Output:
true

Explanation:
[2,4] sums to 6.
6 is a multiple of 6.
```

### Example 2

```text
Input:
nums = [23,2,6,4,7], k = 6

Output:
true

Explanation:
Entire array sum = 42
42 is divisible by 6.
```

### Example 3

```text
Input:
nums = [23,2,6,4,7], k = 13

Output:
false
```

---

# Approach 1 : Brute Force

## Idea

Generate every possible subarray.

For every subarray having length at least 2:

- Calculate its sum.
- Check whether `sum % k == 0`.
- If yes, return `true`.

If no subarray satisfies the condition, return `false`.

---

## Algorithm

1. Start index `i`.
2. End index `j`.
3. Keep adding elements to current sum.
4. Whenever length ≥ 2:
   - Check `sum % k == 0`.

---

## Java Code

```java
class Solution {
    public boolean checkSubarraySum(int[] nums, int k) {

        int n = nums.length;

        for (int i = 0; i < n; i++) {

            int sum = 0;

            for (int j = i; j < n; j++) {

                sum += nums[j];

                if (j - i + 1 >= 2 && sum % k == 0) {
                    return true;
                }
            }
        }

        return false;
    }
}
```

---

## Complexity

- Time : O(n²)
- Space : O(1)

# Approach 2 : Prefix Sum (Still O(n²))

## Idea

Instead of recalculating every subarray sum, first compute prefix sums.

Then,

```
Subarray Sum = prefix[j] - prefix[i]
```

Now checking any subarray becomes O(1).

---

## Algorithm

1. Build prefix array.
2. Try every pair `(i, j)`.
3. Compute subarray sum using prefix.
4. Check divisibility.

---

## Java Code

```java
class Solution {
    public boolean checkSubarraySum(int[] nums, int k) {

        int n = nums.length;

        int[] prefix = new int[n + 1];

        for (int i = 0; i < n; i++) {
            prefix[i + 1] = prefix[i] + nums[i];
        }

        for (int i = 0; i < n; i++) {

            for (int j = i + 1; j < n; j++) {

                int sum = prefix[j + 1] - prefix[i];

                if (sum % k == 0)
                    return true;
            }
        }

        return false;
    }
}
```

---

## Dry Run

```
nums = [23,2,4,6,7]

Prefix:

index : 0 1 2 3 4 5
value : 0 23 25 29 35 42

Subarray (1,2)

sum = prefix[3] - prefix[1]
    = 29 - 23
    = 6

6 % 6 = 0

Return true
```

---

## Complexity

- Time : O(n²)
- Space : O(n)

# Approach 3 : Optimal (HashMap + Prefix Sum Remainder)

## Observation

Suppose

```
prefixSum1 % k = r
prefixSum2 % k = r
```

Then

```
(prefixSum2 - prefixSum1) % k = 0
```

That means

```
Subarray Sum is divisible by k.
```

So instead of storing prefix sums, we only store their remainder.

---

## Why does this work?

Suppose

```
Prefix Sum = 29

29 % 6 = 5
```

Later,

```
Prefix Sum = 35

35 % 6 = 5
```

Difference

```
35 - 29 = 6

6 % 6 = 0
```

Hence the subarray between these two prefix sums has a sum divisible by `k`.

---

## Key Observation

For each remainder:

- Store only its **first occurrence**.
- If the same remainder appears again:
  - Check if the distance between indices is at least 2.
  - If yes, answer is true.

---

## Algorithm

1. Create HashMap.
2. Store

```
remainder 0 → index -1
```

This handles cases where the valid subarray starts from index 0.

3. Traverse the array.

For every number:

```
prefix += nums[i]
remainder = prefix % k
```

If remainder already exists:

```
length = i - previousIndex
```

If

```
length >= 2
```

return true.

Otherwise,

store the remainder only if it is not already present.

---

## Dry Run

### Example

```
nums = [23,2,4,6,7]

k = 6
```

Initially

```
Map

0 → -1
```

---

### i = 0

```
prefix = 23

remainder = 23 % 6 = 5
```

Map

```
0 → -1
5 → 0
```

---

### i = 1

```
prefix = 25

remainder = 1
```

Map

```
0 → -1
5 → 0
1 → 1
```

---

### i = 2

```
prefix = 29

remainder = 5
```

Already exists.

Previous index = 0

Current index = 2

```
2 - 0 = 2
```

Length ≥ 2

Return true.

---

## Java Code

```java
import java.util.HashMap;

class Solution {
    public boolean checkSubarraySum(int[] nums, int k) {

        HashMap<Integer, Integer> map = new HashMap<>();

        map.put(0, -1);

        int prefix = 0;

        for (int i = 0; i < nums.length; i++) {

            prefix += nums[i];

            int rem = prefix % k;

            if (map.containsKey(rem)) {

                if (i - map.get(rem) >= 2)
                    return true;

            } else {

                map.put(rem, i);
            }
        }

        return false;
    }
}
```

---

## Complexity

- Time : **O(n)**
- Space : **O(min(n, k))**

(HashMap stores at most one index for each distinct remainder.)

---

# Why do we store only the first occurrence?

Example

```
Remainder 5 occurs at:

index 2
index 5
index 8
```

Suppose we overwrite:

```
5 → 5
```

Now when we reach index 8

```
8 - 5 = 3
```

But if we had stored

```
5 → 2
```

Then

```
8 - 2 = 6
```

Keeping the earliest occurrence gives the longest possible subarray and avoids missing valid answers.

---

# Why initialize the map with (0 → -1)?

Consider

```
nums = [2,4]

k = 6
```

Running sum:

```
prefix = 6

remainder = 0
```

Without

```
0 → -1
```

there is no earlier index to compare.

With

```
0 → -1
```

Length

```
1 - (-1) = 2
```

Valid answer.

---

# Comparison

| Approach | Time | Space |
|----------|------|-------|
| Brute Force | O(n²) | O(1) |
| Prefix Sum | O(n²) | O(n) |
| HashMap + Prefix Remainder | O(n) | O(min(n, k)) |

---

# Key Interview Points

- Continuous subarray must have **length ≥ 2**.
- Store **remainder**, not prefix sum.
- If two prefix sums have the same remainder, their difference is divisible by `k`.
- Store only the **first occurrence** of each remainder.
- Initialize the map with `(0 → -1)` to handle subarrays starting from index 0.
- Optimal solution runs in **O(n)** time.
