
# 77. Combinations

**Difficulty:** Medium

**Topic:** Backtracking / Recursion

---

# Problem Statement

Given two integers `n` and `k`, return all possible combinations of `k` numbers chosen from the range:

[1, n]

You may return the answer in any order.

Each number can be chosen **at most once**.

---

# Example 1

```text
Input:
n = 4
k = 2

Output:
[
    [1,2],
    [1,3],
    [1,4],
    [2,3],
    [2,4],
    [3,4]
]
```

Explanation:

We need to choose `2` numbers from:

```text
[1,2,3,4]
```

The possible combinations are:

```text
1,2
1,3
1,4
2,3
2,4
3,4
```

---

# Example 2

```text
Input:
n = 1
k = 1

Output:
[
    [1]
]
```

---

# Understanding the Problem

We need to select exactly `k` numbers from `1` to `n`.

For:

```text
n = 4
k = 2
```

We can start with:

```text
1
```

Then choose numbers after `1`:

```text
[1,2]
[1,3]
[1,4]
```

Then start with:

```text
2
```

We cannot choose `1` again because combinations do not care about order.

So:

```text
[2,3]
[2,4]
```

Finally:

```text
[3,4]
```

Notice that:

```text
[1,2]
```

and:

```text
[2,1]
```

are considered the same combination.

Therefore, we only move forward and never choose a previous number again.

---

# Approach 1: Backtracking

## Idea

We build the combination one element at a time.

At every step:

1. Try every number from `start` to `n`.
2. Add the number to `current`.
3. Recursively select the next number.
4. Remove the number after returning.

The pattern is:

```text
Choose
   ↓
Explore
   ↓
Undo
```

The important part is:

```java
backtrack(i + 1);
```

We start from `i + 1` so that the same number is never selected again.

---

## Java Code

```java
import java.util.*;

class Solution {

    public List<List<Integer>> combine(int n, int k) {

        List<List<Integer>> answer = new ArrayList<>();

        backtrack(1, n, k, new ArrayList<>(), answer);

        return answer;
    }

    private void backtrack(
            int start,
            int n,
            int k,
            List<Integer> current,
            List<List<Integer>> answer) {

        // Combination of size k is complete
        if (current.size() == k) {
            answer.add(new ArrayList<>(current));
            return;
        }

        // Try all possible numbers
        for (int i = start; i <= n; i++) {

            // Choose
            current.add(i);

            // Explore
            backtrack(i + 1, n, k, current, answer);

            // Undo choice
            current.remove(current.size() - 1);
        }
    }
}
```

# Approach 2: Backtracking with Pruning

## Idea

The previous solution tries some branches that cannot possibly produce a valid combination.

For example:

```text
n = 4
k = 3
```

If we currently have:

```text
[4]
```

we still need `2` more numbers.

But there are no numbers after `4`.

So this branch is useless.

We can optimize the loop by calculating how many numbers are still needed.

If we need `remaining` elements, we only loop while enough numbers are available.

---

## Java Code

```java
import java.util.*;

class Solution {

    public List<List<Integer>> combine(int n, int k) {

        List<List<Integer>> answer = new ArrayList<>();

        backtrack(1, n, k, new ArrayList<>(), answer);

        return answer;
    }

    private void backtrack(
            int start,
            int n,
            int k,
            List<Integer> current,
            List<List<Integer>> answer) {

        // Combination is complete
        if (current.size() == k) {
            answer.add(new ArrayList<>(current));
            return;
        }

        int remaining = k - current.size();

        /*
         * We need 'remaining' numbers.
         *
         * If we start at i, we need enough numbers
         * from i to n.
         */
        for (int i = start; i <= n - remaining + 1; i++) {

            // Choose
            current.add(i);

            // Explore
            backtrack(i + 1, n, k, current, answer);

            // Undo
            current.remove(current.size() - 1);
        }
    }
}
```

# Approach 3: Backtracking with Early Stop

## Idea

Another simple optimization is to stop recursion when the current combination can no longer reach size `k`.

For example:

```text
current.size() + (n - start + 1) < k
```

means:

```text
Even if we choose every remaining number,
we still cannot reach k elements.
```

So we can immediately return.

---

## Java Code

```java
import java.util.*;

class Solution {

    public List<List<Integer>> combine(int n, int k) {

        List<List<Integer>> answer = new ArrayList<>();

        backtrack(1, n, k, new ArrayList<>(), answer);

        return answer;
    }

    private void backtrack(
            int start,
            int n,
            int k,
            List<Integer> current,
            List<List<Integer>> answer) {

        if (current.size() == k) {
            answer.add(new ArrayList<>(current));
            return;
        }

        // Not enough elements remain
        if (current.size() + (n - start + 1) < k) {
            return;
        }

        for (int i = start; i <= n; i++) {

            current.add(i);

            backtrack(i + 1, n, k, current, answer);

            current.remove(current.size() - 1);
        }
    }
}
```


# Complexity

The total number of combinations is:

```text
C(n, k)
```

Each combination contains `k` elements.

Therefore:

```text
Time: O(C(n,k) × k)
```

Output space:

```text
O(C(n,k) × k)
```

Recursion / auxiliary space:

```text
O(k)
```

---

# Comparison

| Approach           | Time          | Auxiliary Space | Optimization | Main Idea                                     |
| ------------------ | ------------- | --------------- | ------------ | --------------------------------------------- |
| Basic Backtracking | O(C(n,k) × k) | O(k)            | No           | Try every possible choice                     |
| Pruned Loop        | O(C(n,k) × k) | O(k)            | Yes          | Avoid impossible starting positions           |
| Early Stop         | O(C(n,k) × k) | O(k)            | Yes          | Stop when remaining elements are insufficient |

# Which Approach Is Better?

## Best Basic Approach: Backtracking

The first approach is the easiest to understand.

It clearly demonstrates the core backtracking pattern:

```text
Choose
   ↓
Explore
   ↓
Undo
```

This is the best approach for learning the concept.

---

## Best Overall: Backtracking with Pruning

The second approach is generally the best implementation.

The important optimization is:

```java
i <= n - remaining + 1
```

It prevents us from exploring branches that cannot possibly produce `k` elements.

For example:

```text
n = 4
k = 3
```

We don't need to start a combination with `3` or `4` because there aren't enough elements remaining.

This makes the recursion tree smaller and avoids unnecessary calls.

# Key Difference from Permutations

## Permutations

Order matters:

```text
[1,2]
[2,1]
```

Both are different.

---

## Combinations

Order does not matter:

```text
[1,2]
[2,1]
```

These are the same.

Therefore, after choosing `i`, we only consider:

```java
backtrack(i + 1, ...)
```

This ensures that we never go backward and generate duplicates.

---

# Important Pattern

For combinations:

```text
Choose i
   ↓
Only consider i + 1 onwards
   ↓
Explore
   ↓
Undo
```

The key line is:

```java
backtrack(i + 1, n, k, current, answer);
```

This is what prevents duplicate combinations.

---

# Permutations vs Combinations

| Feature            | Permutations        | Combinations  |
| ------------------ | ------------------- | ------------- |
| Order matters      | Yes                 | No            |
| `[1,2]` vs `[2,1]` | Different           | Same          |
| Common technique   | `used[]` / swapping | `start` index |
| Example            | `[1,2]`, `[2,1]`    | `[1,2]` only  |
| Number of results  | `n!`                | `C(n,k)`      |

---

# Key Interview Takeaways

* Use **Backtracking** to generate combinations.
* Use a `start` index to avoid duplicates.
* Move to `i + 1` after selecting an element.
* Stop when `current.size() == k`.
* Pruning can reduce unnecessary recursion.
* The number of combinations is:

```text
C(n,k) = n! / (k! × (n-k)!)
```

* Core pattern:

```text
Choose
   ↓
Explore
   ↓
Undo
```

* For combinations, the key difference from permutations is that we move **forward using `start`** instead of tracking every element with `used[]`.
