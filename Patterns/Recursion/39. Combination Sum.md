# 39. Combination Sum

**Difficulty:** Medium

**Topic:** Backtracking / Recursion

---

# Problem Statement

Given an array of **distinct integers** `candidates` and an integer `target`, return a list of all unique combinations of `candidates` where the chosen numbers sum to `target`.

You may choose the same number from `candidates` **unlimited times**.

The combinations can be returned in any order.

Two combinations are considered different if the frequency of at least one chosen number is different.

---

# Example 1

```text
Input:
candidates = [2,3,6,7]
target = 7

Output:
[
    [2,2,3],
    [7]
]
```

Explanation:

```text
2 + 2 + 3 = 7
7 = 7
```

The combination:

```text
[2,3,2]
```

is not considered different from:

```text
[2,2,3]
```

because the order does not matter.

---

# Example 2

```text
Input:
candidates = [2,3,5]
target = 8

Output:
[
    [2,2,2,2],
    [2,3,3],
    [3,5]
]
```

---

# Example 3

```text
Input:
candidates = [2]
target = 1

Output:
[]
```

There is no combination whose sum is `1`.

---

# Understanding the Problem

We need to find all combinations whose sum is exactly `target`.

For:

```text
candidates = [2,3,6,7]
target = 7
```

We can choose:

```text
2 → remaining = 5
2 → remaining = 3
3 → remaining = 0
```

So:

```text
[2,2,3]
```

is a valid answer.

We can also directly choose:

```text
7 → remaining = 0
```

So:

```text
[7]
```

is another answer.

The important point is that we can reuse the same number.

For example:

```text
[2,2,3]
```

is allowed.

---

# Approach 1: Basic Backtracking

## Idea

We maintain:

```text
current
```

to store the current combination.

At every step:

1. Try each candidate.
2. Subtract it from the remaining target.
3. Add it to `current`.
4. Recursively search for the remaining target.
5. Remove it when backtracking.

Because we are allowed to reuse elements, we call:

```java
backtrack(i, ...)
```

instead of:

```java
backtrack(i + 1, ...)
```

This is the key difference from **LeetCode 77 — Combinations**.

---

## Java Code

```java
import java.util.*;

class Solution {

    public List<List<Integer>> combinationSum(
            int[] candidates,
            int target) {

        List<List<Integer>> answer = new ArrayList<>();

        backtrack(
                candidates,
                target,
                0,
                new ArrayList<>(),
                answer
        );

        return answer;
    }

    private void backtrack(
            int[] candidates,
            int target,
            int start,
            List<Integer> current,
            List<List<Integer>> answer) {

        // Valid combination found
        if (target == 0) {
            answer.add(new ArrayList<>(current));
            return;
        }

        for (int i = start; i < candidates.length; i++) {

            // Skip candidate if it exceeds remaining target
            if (candidates[i] > target) {
                continue;
            }

            // Choose
            current.add(candidates[i]);

            // Explore
            // Use i again because repetition is allowed
            backtrack(
                    candidates,
                    target - candidates[i],
                    i,
                    current,
                    answer
            );

            // Undo choice
            current.remove(current.size() - 1);
        }
    }
}
```

# Approach 2: Backtracking with Sorting and Pruning

## Idea

We first sort the candidates.

For example:

```text
[2,3,6,7]
```

Then, because the array is sorted, if:

```text
candidates[i] > target
```

all following candidates will also be greater than `target`.

So instead of:

```java
continue;
```

we can directly:

```java
break;
```

This avoids unnecessary iterations.

---

## Java Code

```java
import java.util.*;

class Solution {

    public List<List<Integer>> combinationSum(
            int[] candidates,
            int target) {

        Arrays.sort(candidates);

        List<List<Integer>> answer = new ArrayList<>();

        backtrack(
                candidates,
                target,
                0,
                new ArrayList<>(),
                answer
        );

        return answer;
    }

    private void backtrack(
            int[] candidates,
            int target,
            int start,
            List<Integer> current,
            List<List<Integer>> answer) {

        if (target == 0) {
            answer.add(new ArrayList<>(current));
            return;
        }

        for (int i = start; i < candidates.length; i++) {

            // Since array is sorted,
            // all further values will also be too large
            if (candidates[i] > target) {
                break;
            }

            // Choose
            current.add(candidates[i]);

            // Reuse current element
            backtrack(
                    candidates,
                    target - candidates[i],
                    i,
                    current,
                    answer
            );

            // Undo
            current.remove(current.size() - 1);
        }
    }
}
```

# Approach 3: Backtracking with Explicit Remaining Sum

## Idea

Instead of changing the `target` variable itself, we can maintain a variable:

```text
remaining
```

The logic becomes easier to visualize:

```text
remaining = target
       ↓
choose candidate
       ↓
remaining -= candidate
       ↓
remaining == 0 ?
```

This is logically the same as Approach 2, but the naming makes the recursion easier to understand.

We also use a helper method that returns immediately when the remaining sum becomes negative.

---

## Java Code

```java
import java.util.*;

class Solution {

    public List<List<Integer>> combinationSum(
            int[] candidates,
            int target) {

        List<List<Integer>> answer = new ArrayList<>();

        Arrays.sort(candidates);

        backtrack(
                candidates,
                target,
                0,
                new ArrayList<>(),
                answer
        );

        return answer;
    }

    private void backtrack(
            int[] candidates,
            int remaining,
            int start,
            List<Integer> current,
            List<List<Integer>> answer) {

        // Target reached
        if (remaining == 0) {
            answer.add(new ArrayList<>(current));
            return;
        }

        // Target exceeded
        if (remaining < 0) {
            return;
        }

        for (int i = start; i < candidates.length; i++) {

            // No need to check larger values
            if (candidates[i] > remaining) {
                break;
            }

            current.add(candidates[i]);

            // Same i because reuse is allowed
            backtrack(
                    candidates,
                    remaining - candidates[i],
                    i,
                    current,
                    answer
            );

            current.remove(current.size() - 1);
        }
    }
}
```

# Why Don't We Use `i + 1`?

This is one of the most important points.

In **LeetCode 77 — Combinations**, we use:

```java
backtrack(i + 1, ...)
```

because every number can be used only once.

But in **Combination Sum**, we can reuse a number.

Therefore:

```java
backtrack(i, ...)
```

is used.

Example:

```text
candidates = [2,3]
target = 6
```

We need:

```text
2 + 2 + 2 = 6
```

If we use:

```java
backtrack(i + 1, ...)
```

we would not be able to select `2` again.

So we use:

```java
backtrack(i, ...)
```

---

# Why Don't We Generate Duplicates?

Suppose:

```text
[2,3]
```

We could potentially generate:

```text
[2,3]
[3,2]
```

But these represent the same combination.

To prevent this, we maintain a `start` index.

Once we choose `2`, we only consider:

```text
2 → 3 → ...
```

We never go backward to choose an earlier candidate.

Therefore:

```text
[2,3]
```

is generated, but:

```text
[3,2]
```

is never generated.

# Comparison

| Approach | Sorting | Reuse | Pruning | Readability | Recommendation |
|----------|---------|-------|---------|-------------|----------------|
| Basic Backtracking | No | `i` | Basic | Easy | Good for learning |
| Sorted + Pruning | Yes | `i` | Strong | Easy | Best overall |
| Explicit `remaining` | Yes | `i` | Strong | Very Easy | Best for understanding |

---

# Which Approach Is Better?

## Best Overall: Sorting + Pruning

The second approach is generally the best solution.

The important optimization is:

```java
if (candidates[i] > target) {
    break;
}
```

Because the candidates are sorted, once one candidate is too large, every candidate after it will also be too large.

This avoids unnecessary recursion.

---

## Best for Beginners: Explicit `remaining`

The third approach is also excellent for learning.

The variable:

```text
remaining
```

makes the recursive state very clear.

For example:

```text
target = 8

choose 3
remaining = 8 - 3 = 5

choose 5
remaining = 5 - 5 = 0

valid combination
```

This is often easier to visualize during a dry run.

# Complexity

Let:

```text
N = number of candidates
T = target
```

The exact complexity depends on the values in `candidates`.

In the worst case, the number of possible combinations can grow exponentially.

A commonly used upper-bound representation is:

```text
Time: O(N^(T/M))
```

where `M` is the smallest candidate.

The output itself can require:

```text
O(K × L)
```

space, where:

- `K` = number of valid combinations
- `L` = average length of a combination

Recursion depth is at most:

```text
O(T / M)
```

# Key Difference: Combination Sum vs Combinations

| Feature | LeetCode 77 | LeetCode 39 |
|---------|--------------|--------------|
| Problem | Combinations | Combination Sum |
| Input | `1` to `n` | `candidates[]` |
| Fixed size | Yes, exactly `k` | No |
| Target sum | No | Yes |
| Reuse elements | No | Yes |
| Recursive call | `i + 1` | `i` |
| Main condition | `current.size() == k` | `remaining == 0` |

# Backtracking Pattern

The core pattern is:

```text
Choose
   ↓
Reduce Remaining Target
   ↓
Explore
   ↓
Undo Choice
```

In code:

```java
current.add(candidates[i]);

backtrack(
    candidates,
    remaining - candidates[i],
    i,
    current,
    answer
);

current.remove(current.size() - 1);
```

# Key Interview Takeaways

- Use **Backtracking** to generate all valid combinations.
- The same candidate can be selected **multiple times**.
- Use `i`, not `i + 1`, when recursively calling the function.
- Use a `start` index to avoid duplicate combinations.
- Sorting enables effective pruning.
- If `candidates[i] > remaining`, we can `break` because the array is sorted.
- `remaining == 0` means a valid combination is found.
- `remaining < 0` means the current branch is invalid.
- Core pattern:

```text
Choose
   ↓
Explore
   ↓
Undo
```

- The most important line for reuse is:

```java
backtrack(..., i, ...);
```

- The most important line for avoiding duplicates is:

```java
for (int i = start; i < candidates.length; i++)
```
