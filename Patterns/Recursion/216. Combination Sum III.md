# 216. Combination Sum III

**Difficulty:** Medium

**Topic:** Backtracking / Recursion

---

# Problem Statement

Find all valid combinations of `k` numbers that add up to `n` such that:

- Only numbers from `1` to `9` are used.
- Each number can be used **at most once**.
- The combination must contain exactly `k` numbers.
- The same combination should not appear more than once.

Return all possible valid combinations.

---

# Example 1

```text
Input:
k = 3
n = 7

Output:
[
    [1,2,4]
]
```

Explanation:

```text
1 + 2 + 4 = 7
```

There is no other combination of exactly `3` distinct numbers from `1` to `9` that sums to `7`.

```text
[
    [1,2,6],
    [1,3,5],
    [2,3,4]
]
```

Explanation:

```text
1 + 2 + 6 = 9
1 + 3 + 5 = 9
2 + 3 + 4 = 9
```

---

# Example 3

```text
Input:

n = 1

[]
```

# Understanding the Problem

We need to select:

```text
Exactly k numbers
```

from:

```text
1,2,3,4,5,6,7,8,9
```

The selected numbers must have a sum of:

```text
n
```

For example:

```text
k = 3
n = 9
```

We need exactly `3` numbers.

One valid combination is:

```text
[1,2,6]
```

because:

```text
1 + 2 + 6 = 9
```

We cannot use the same number twice.

So this is invalid:

```text
[3,3,3]
```

Also, order does not matter.

Therefore:

```text
[1,2,6]
```

and:

```text
[6,2,1]
```

represent the same combination.

We only generate numbers in increasing order to avoid duplicates.

---

# Approach 1: Basic Backtracking

## Idea

We use backtracking to select numbers from `1` to `9`.

We maintain:

```text
current
```

to store the selected numbers.

At every step:

1. Try numbers from `start` to `9`.
2. Add the current number.
3. Reduce the remaining target.
4. Recursively select the next number.
5. Remove the number while backtracking.

We move to:

```java
i + 1
```

because each number can only be used once.

---

## Java Code

```java
import java.util.*;

class Solution {

    public List<List<Integer>> combinationSum3(int k, int n) {

        List<List<Integer>> answer = new ArrayList<>();

        backtrack(
                1,
                k,
                n,
                new ArrayList<>(),
                answer
        );

        return answer;
    }

    private void backtrack(
            int start,
            int k,
            int target,
            List<Integer> current,
            List<List<Integer>> answer) {

        // Valid combination found
        if (current.size() == k) {

            if (target == 0) {
                answer.add(new ArrayList<>(current));
            }

            return;
        }

        // Try numbers from start to 9
        for (int i = start; i <= 9; i++) {

            // Choose
            current.add(i);

            // Explore
            backtrack(
                    i + 1,
                    k,
                    target - i,
                    current,
                    answer
            );

            // Undo
            current.remove(current.size() - 1);
        }
    }
}
```

# Approach 2: Backtracking with Pruning

## Idea

The basic approach explores many unnecessary branches.

We can stop early when:

```text
target < 0
```

because adding more positive numbers can never bring the target back to `0`.

We can also stop when:

```text
current.size() == k
```

because we cannot select any more numbers.

This gives us a cleaner and more efficient search.

---

## Java Code

```java
import java.util.*;

class Solution {

    public List<List<Integer>> combinationSum3(int k, int n) {

        List<List<Integer>> answer = new ArrayList<>();

        backtrack(
                1,
                k,
                n,
                new ArrayList<>(),
                answer
        );

        return answer;
    }

    private void backtrack(
            int start,
            int k,
            int target,
            List<Integer> current,
            List<List<Integer>> answer) {

        // Target exceeded
        if (target < 0) {
            return;
        }

        // We have selected k numbers
        if (current.size() == k) {

            if (target == 0) {
                answer.add(new ArrayList<>(current));
            }

            return;
        }

        for (int i = start; i <= 9; i++) {

            // Choose
            current.add(i);

            // Explore
            backtrack(
                    i + 1,
                    k,
                    target - i,
                    current,
                    answer
            );

            // Undo
            current.remove(current.size() - 1);
        }
    }
}
```

# Approach 3: Backtracking with Strong Pruning

## Idea

We can improve the solution further by stopping a branch when it is mathematically impossible to complete the combination.

We need:

```text
remaining = k - current.size()
```

numbers.

If there are not enough numbers remaining, we stop.

We can also stop when the current target cannot be reached using the smallest possible remaining numbers.

This reduces unnecessary recursive calls.

---

## Java Code

```java
import java.util.*;

class Solution {

    public List<List<Integer>> combinationSum3(int k, int n) {

        List<List<Integer>> answer = new ArrayList<>();

        backtrack(
                1,
                k,
                n,
                new ArrayList<>(),
                answer
        );

        return answer;
    }

    private void backtrack(
            int start,
            int k,
            int target,
            List<Integer> current,
            List<List<Integer>> answer) {

        int remaining = k - current.size();

        // Not enough numbers available
        if (9 - start + 1 < remaining) {
            return;
        }

        // Target exceeded
        if (target < 0) {
            return;
        }

        // All required numbers selected
        if (remaining == 0) {

            if (target == 0) {
                answer.add(new ArrayList<>(current));
            }

            return;
        }

        for (int i = start; i <= 9; i++) {

            // Choose
            current.add(i);

            // Explore
            backtrack(
                    i + 1,
                    k,
                    target - i,
                    current,
                    answer
            );

            // Undo
            current.remove(current.size() - 1);
        }
    }
}
```

# Comparison

| Approach | Pruning | Time | Auxiliary Space | Best For |
|----------|---------|------|------------------|----------|
| Basic Backtracking | No | Exponential | O(k) | Understanding recursion |
| Basic + Target Pruning | `target < 0` | Exponential | O(k) | Simple optimization |
| Strong Pruning | Target + remaining numbers | Exponential | O(k) | Best optimized solution |

# Which Approach Is Better?

## Best for Learning: Basic Backtracking

The first approach is the easiest to understand.

The core logic is:

```text
Choose a number
      ↓
Move to next number
      ↓
Reduce target
      ↓
Backtrack
```

It is useful for understanding how the solution is built.

---

## Best Overall: Strong Pruning

The third approach is the best optimized version.

The search space is already small because we only have numbers:

```text
1 to 9
```

But pruning prevents exploring branches that cannot possibly form a valid combination.

The important conditions are:

```java
if (target < 0) {
    return;
}
```

and:

```java
if (9 - start + 1 < remaining) {
    return;
}
```

This makes the recursion more efficient.

# Why Do We Use `i + 1`?

Unlike **LeetCode 39 — Combination Sum**, we cannot reuse a number.

For example, this is invalid:

```text
[2,2,5]
```

because each number can only be used once.

Therefore, after choosing `i`, we move to:

```java
i + 1
```

So:

```java
backtrack(i + 1, ...)
```

is used.

---

# Combination Sum vs Combination Sum III

| Feature | LeetCode 39 | LeetCode 216 |
|---------|-------------|--------------|
| Candidates | Given array | `1` to `9` |
| Exact number of elements | No | Yes, exactly `k` |
| Target sum | Yes | Yes |
| Reuse elements | Yes | No |
| Recursive call | `i` | `i + 1` |
| Duplicate values | Candidates are distinct | Numbers are naturally distinct |
| Main stopping condition | `target == 0` | `size == k && target == 0` |

# Combinations vs Combination Sum III

| Feature | LeetCode 77 | LeetCode 216 |
|---------|-------------|--------------|
| Choose from | `1` to `n` | `1` to `9` |
| Exact size | `k` | `k` |
| Target sum | No | Yes |

The main difference is that **Combination Sum III** has an additional target-sum constraint.

# Complexity

Since the input range is fixed to:

```text
1 to 9
```

there are at most:

```text
C(9, k)
```

possible combinations.

Each valid combination contains `k` elements.

Therefore, the output-related complexity is approximately:

```text
Time: O(C(9,k) × k)
```

Auxiliary recursion space:

```text
O(k)
```

Output space:

```text
O(C(9,k) × k)
```

Because `k <= 9`, the search space is very small.

# Key Interview Takeaways

- Use **Backtracking** to generate possible combinations.
- Numbers are restricted to `1` through `9`.
- Each number can be used **only once**.
- The combination must contain exactly `k` numbers.
- The sum must be exactly `n`.
- Use `i + 1` because numbers cannot be reused.
- Use a `start` index to avoid duplicate combinations.
- Stop when `current.size() == k`.
- A valid answer requires:

```text
current.size() == k
AND
target == 0
```

- Prune when:

```java
target < 0
```

- Core pattern:

```text
Choose
   ↓
Explore
   ↓
Undo
```

- The most important difference from **LeetCode 39** is:

```text
LeetCode 39 → reuse allowed → backtrack(i)
LeetCode 216 → reuse not allowed → backtrack(i + 1)
```
