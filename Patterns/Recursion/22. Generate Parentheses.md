# LeetCode 22 — Generate Parentheses

**Difficulty:** Medium  
**Topics:** Backtracking, Recursion, String

---

## Problem Statement

Given an integer `n`, generate all combinations of **well-formed parentheses** using exactly `n` pairs of parentheses.

---

## Example 1

```text
Input:
n = 3

Output:
["((()))", "(()())", "(())()", "()(())", "()()()"]
```

---

## Example 2

```text
Input:
n = 1

Output:
["()"]
```

---

## What Is a Valid Parentheses String?

For every valid combination:

1. We must use exactly `n` opening brackets `(`.
2. We must use exactly `n` closing brackets `)`.
3. At any point, the number of closing brackets cannot be greater than the number of opening brackets.

For:

```text
n = 3
```

Valid:

```text
((()))
(()())
(())()
()(())
()()()
```

Invalid:

```text
((()
())(
)(
```

---

# Main Idea — Backtracking

At every step, we have two choices:

```text
Add '('
Add ')'
```

But we can only add them under certain conditions.

### Add Opening Bracket

We can add `(` if:

```java
open < n
```

### Add Closing Bracket

We can add `)` if:

```java
close < open
```

Why?

Because we cannot close a bracket that hasn't been opened yet.

For example:

```text
")("
```

is invalid.

At the beginning:

```text
open = 0
close = 0
```

We cannot add `)` because:

```text
close < open
0 < 0 → false
```

So we must start with:

```text
(
```

---

# Approach 1: Brute Force

We can generate all possible strings of length:

```text
2 × n
```

Each position has two choices:

```text
(
)
```

Therefore, there are:

```text
2^(2n)
```

possible strings.

Then we check which ones are valid.

For example, for:

```text
n = 3
```

we generate strings of length `6`:

```text
((()))
(()())
...
```

and check each one.

This works for small `n`, but it generates many invalid combinations.

For example:

```text
)))(((
```

is obviously invalid, but brute force still generates it.

So we use backtracking to avoid invalid paths early.

---

# Approach 2: Backtracking

## Java Code

```java
class Solution {
    public List<String> generateParenthesis(int n) {
        List<String> result = new ArrayList<>();
        backtrack(n, 0, 0, new StringBuilder(), result);
        return result;
    }

    private void backtrack(int n, int open, int close, StringBuilder current, List<String> result) {
        if (current.length() == 2 * n) {
            result.add(current.toString());
            return;
        }

        if (open < n) {
            current.append('(');
            backtrack(n, open + 1, close, current, result);
            current.deleteCharAt(current.length() - 1);
        }

        if (close < open) {
            current.append(')');
            backtrack(n, open, close + 1, current, result);
            current.deleteCharAt(current.length() - 1);
        }
    }
}
```

# Why Do We Need `close < open`?

Suppose:

```text
current = "("
```

We have:

```text
open = 1
close = 0
```

We can add:

```text
)
```

because:

```text
close < open
0 < 1
```

Now:

```text
current = "()"
open = 1
close = 1
```

We cannot add another `)`:

```text
close < open
1 < 1 → false
```

If we allowed it, we would get:

```text
())
```

which is invalid.

So:

```java
if (close < open)
```

ensures that we never have more closing brackets than opening brackets.

---

# Why Do We Need `open < n`?

For:

```text
n = 3
```

we can use exactly:

```text
3 opening brackets
3 closing brackets
```

Once:

```text
open == n
```

we cannot add any more `(`.

Therefore:

```java
if (open < n)
```

ensures we don't use more than `n` opening brackets.

# Approach 3: Backtracking Using String Instead of StringBuilder

We can also use a normal `String`.

## Java Code

```java
class Solution {
    public List<String> generateParenthesis(int n) {
        List<String> result = new ArrayList<>();
        backtrack(n, 0, 0, "", result);
        return result;
    }

    private void backtrack(int n, int open, int close, String current, List<String> result) {
        if (current.length() == 2 * n) {
            result.add(current);
            return;
        }

        if (open < n) {
            backtrack(n, open + 1, close, current + "(", result);
        }

        if (close < open) {
            backtrack(n, open, close + 1, current + ")", result);
        }
    }
}
```

This is easier to understand because strings are immutable and we don't need:

```java
append()
deleteCharAt()
```

However, every:

```java
current + "("
```

creates a new String.

So `StringBuilder` is generally more efficient.

# Approach 4: Generate All and Validate

Another approach is to generate every possible string of length `2n`.

At each position:

```text
Choose '('
or
Choose ')'
```

After generating a complete string, check if it is valid.

## Java Code

```java
class Solution {
    public List<String> generateParenthesis(int n) {
        List<String> result = new ArrayList<>();
        generate(n, "", result);
        return result;
    }

    private void generate(int n, String current, List<String> result) {
        if (current.length() == 2 * n) {
            if (isValid(current)) {
                result.add(current);
            }
            return;
        }

        generate(n, current + "(", result);
        generate(n, current + ")", result);
    }

    private boolean isValid(String s) {
        int balance = 0;

        for (char ch : s.toCharArray()) {
            if (ch == '(') {
                balance++;
            } else {
                balance--;
            }

            if (balance < 0) {
                return false;
            }
        }

        return balance == 0;
    }
}
```

# Complexity Comparison

The number of valid parentheses combinations is the `n`th **Catalan number**:

```text
C(n) = (1 / (n + 1)) × C(2n, n)
```

The number of valid results grows very quickly.

| Approach | Idea | Efficiency |
|---|---|---|
| Brute Force | Generate all `2^(2n)` strings and validate | Worst |
| Backtracking | Avoid invalid paths early | Best |
| String Backtracking | Same logic using String | Good |
| StringBuilder Backtracking | Same logic with mutable string | Best practical choice |

---

# Which Approach Is Better?

The **Backtracking approach** is the best.

Instead of generating invalid strings like:

```text
)))
```

we stop immediately because:

```text
close > open
```

The main conditions are:

```java
if (open < n)
```

Add:

```text
(
```

And:

```java
if (close < open)
```

Add:

```text
)
```

# Final Recommended Solution

```java
class Solution {
    public List<String> generateParenthesis(int n) {
        List<String> result = new ArrayList<>();
        backtrack(n, 0, 0, new StringBuilder(), result);
        return result;
    }

    private void backtrack(int n, int open, int close, StringBuilder current, List<String> result) {
        if (current.length() == 2 * n) {
            result.add(current.toString());
            return;
        }

        if (open < n) {
            current.append('(');
            backtrack(n, open + 1, close, current, result);
            current.deleteCharAt(current.length() - 1);
        }

        if (close < open) {
            current.append(')');
            backtrack(n, open, close + 1, current, result);
            current.deleteCharAt(current.length() - 1);
        }
    }
}
```

**Time Complexity:** `O(C(n) × n)`  
**Space Complexity:** `O(n)` recursion stack, excluding the output.

Where `C(n)` is the `n`th Catalan number.

# Core Pattern to Remember

For generating valid parentheses:

```text
open < n
    ↓
Can add '('

close < open
    ↓
Can add ')'

length == 2 × n
    ↓
Valid complete answer
```

The key idea is:

```text
Never allow close > open
```

This single condition prevents invalid parentheses combinations from being generated.
