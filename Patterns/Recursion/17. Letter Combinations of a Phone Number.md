# LeetCode 17 — Letter Combinations of a Phone Number

**Difficulty:** Medium  
**Topics:** Backtracking, Recursion, String

---

## Problem Statement

Given a string containing digits from `2` to `9`, return all possible letter combinations that the number could represent.

The mapping is the same as on a traditional phone keypad:

```text
2 → abc
3 → def
4 → ghi
5 → jkl
6 → mno
7 → pqrs
8 → tuv
9 → wxyz
```

Return the combinations in any order.

If the input is empty, return an empty list.

---

```text
Input:
digits = "23"

Output:

```

Explanation:

```text

```

We choose one character from each digit:

```text

b + e = be
b + f = bf

c + d = cd
c + e = ce
c + f = cf
```

Total combinations:

```text
3 × 3 = 9
```

# Main Idea

This is a classic **Backtracking** problem.

For every digit, we have multiple character choices.

For example:

```text
digits = "23"
```

The decision tree looks like:

```text
                 ""
              /  |  \
             a   b   c
            /|\ /|\ /|\
           d e f d e f d e f
```

The final combinations are:

```text
ad ae af
bd be bf
cd ce cf
```

We process the digits one by one.

At every step:

1. Get the letters corresponding to the current digit.
2. Try each letter.
3. Add it to the current combination.
4. Move to the next digit.
5. Remove the character and try the next option.

# Approach 1: Backtracking

## Java Code

```java
class Solution {
    public List<String> letterCombinations(String digits) {
        List<String> result = new ArrayList<>();

        if (digits.length() == 0) {
            return result;
        }

        String[] mapping = {
            "", "", "abc", "def", "ghi",
            "jkl", "mno", "pqrs", "tuv", "wxyz"
        };

        backtrack(digits, 0, new StringBuilder(), result, mapping);

        return result;
    }

    private void backtrack(String digits, int index, StringBuilder current, List<String> result, String[] mapping) {
        if (index == digits.length()) {
            result.add(current.toString());
            return;
        }

        String letters = mapping[digits.charAt(index) - '0'];

        for (char letter : letters.toCharArray()) {
            current.append(letter);

            backtrack(digits, index + 1, current, result, mapping);

            current.deleteCharAt(current.length() - 1);
        }
    }
}
```

# Why Do We Backtrack?

Suppose we choose:

```text
a
```

Then:

```text
ad
```

After adding `"ad"` to the result, we need to try:

```text
ae
```

So we remove:

```text
d
```

from the current string:

```text
"ad" → "a"
```

Then add:

```text
e
```

```text
"a" → "ae"
```

This is backtracking:

```text
Choose
  ↓
Explore
  ↓
Undo
  ↓
Choose next option
```

The important code is:

```java
current.append(letter);

backtrack(...);

current.deleteCharAt(current.length() - 1);
```

# Approach 2: Backtracking Using String

Instead of using `StringBuilder`, we can directly create a new String at every recursive call.

## Java Code

```java
class Solution {
    public List<String> letterCombinations(String digits) {
        List<String> result = new ArrayList<>();

        if (digits.length() == 0) {
            return result;
        }

        String[] mapping = {
            "", "", "abc", "def", "ghi",
            "jkl", "mno", "pqrs", "tuv", "wxyz"
        };

        backtrack(digits, 0, "", result, mapping);

        return result;
    }

    private void backtrack(String digits, int index, String current, List<String> result, String[] mapping) {
        if (index == digits.length()) {
            result.add(current);
            return;
        }

        String letters = mapping[digits.charAt(index) - '0'];

        for (char letter : letters.toCharArray()) {
            backtrack(digits, index + 1, current + letter, result, mapping);
        }
    }
}
```

This version is simpler because we don't need:

```java
append()
deleteCharAt()
```

But Strings are immutable in Java.

So:

```java
current + letter
```

creates a new String each time.

For this problem, the input size is small, so this is still acceptable.

# Approach 3: Iterative / BFS

We can also solve this problem without recursion.

Start with:

```text
[]
```

For every digit, add each possible letter to every existing combination.

For:

```text
digits = "23"
```

Start:

```text
[""]
```

Process `2`:

```text
["a", "b", "c"]
```

Process `3`:

```text
["ad", "ae", "af",
 "bd", "be", "bf",
 "cd", "ce", "cf"]
```

---

## Java Code

```java
class Solution {
    public List<String> letterCombinations(String digits) {
        List<String> result = new ArrayList<>();

        if (digits.length() == 0) {
            return result;
        }

        String[] mapping = {
            "", "", "abc", "def", "ghi",
            "jkl", "mno", "pqrs", "tuv", "wxyz"
        };

        result.add("");

        for (char digit : digits.toCharArray()) {
            String letters = mapping[digit - '0'];
            List<String> next = new ArrayList<>();

            for (String combination : result) {
                for (char letter : letters.toCharArray()) {
                    next.add(combination + letter);
                }
            }

            result = next;
        }

        return result;
    }
}
```

# Complexity

Let:

```text
n = number of digits
```

Each digit has at most `4` letters.

Maximum number of combinations:

```text
4^n
```

Each combination has length `n`.

Therefore:

```text
Time: O(4^n × n)
```

The output itself requires:

```text
O(4^n × n)
```

space.

The recursion stack requires:

```text
O(n)
```

additional space.

# Which Approach Is Better?

I recommend **Backtracking + StringBuilder**.

Why?

Because the problem naturally represents a decision tree:

```text
Each digit
    ↓
Multiple character choices
    ↓
Choose one
    ↓
Move to next digit
    ↓
Backtrack
```

`StringBuilder` also avoids creating a new String every time we add a character.

The main pattern is:

```java
current.append(letter);
backtrack(...);
current.deleteCharAt(current.length() - 1);
```

# Core Pattern to Remember

This is a **Backtracking / Cartesian Product** problem.

```text
digits = "23"

2 → a b c
3 → d e f

Choose from 2
      ↓
Choose from 3
      ↓
Create combination
      ↓
Backtrack
      ↓
Try next choice
```

The key template is:

```text
if (reached end)
    add answer

for every possible choice:
    make choice
    recurse
    undo choice
```

This same backtracking pattern appears in:

```text
LeetCode 17 → Letter Combinations
LeetCode 22 → Generate Parentheses
LeetCode 39 → Combination Sum
LeetCode 46 → Permutations
LeetCode 51 → N-Queens
LeetCode 77 → Combinations
LeetCode 216 → Combination Sum III
```
