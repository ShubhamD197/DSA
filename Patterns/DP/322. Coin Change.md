# LeetCode 322 — Coin Change

**Difficulty:** Medium  
**Topics:** Dynamic Programming, Unbounded Knapsack

---

## Problem Statement

You are given an integer array `coins`, where:

```text
coins[i] = value of a coin
```

You are also given an integer `amount`.

Return the **fewest number of coins** needed to make up the given `amount`.

You can use each coin **unlimited times**.

If the amount cannot be made using the given coins, return:

```text
-1
```

---

## Example 1

```text
Input:
coins = [1, 2, 5]
amount = 11

Output:
3
```

Explanation:

```text
11 = 5 + 5 + 1
```

Number of coins:

```text
3
```

---

## Example 2

```text
Input:
coins = [2]
amount = 3

Output:
-1
```

It is impossible to make `3` using only coins of value `2`.

---

## Example 3

```text
Input:
coins = [1]
amount = 0

Output:
0
```

We need zero coins to make amount `0`.

---

# Main Idea

We need to find the **minimum number of coins**.

For every amount, we try using each available coin.

For example:

```text
coins = [1, 2, 5]
amount = 11
```

To make `11`, we can choose:

```text
1 → remaining amount = 10
2 → remaining amount = 9
5 → remaining amount = 6
```

Then we solve the smaller remaining amount.

This gives the recurrence:

```text
dp[amount] = 1 + min(dp[amount - coin])
```

for every valid coin.

---

# Approach 1: Brute Force Recursion

We can recursively try every possible coin.

For:

```text
coins = [1, 2, 5]
amount = 11
```

We try:

```text
11 - 1 = 10
11 - 2 = 9
11 - 5 = 6
```

Then solve:

```text
10, 9, 6
```

and continue until we reach `0`.

The problem is that the same amounts are calculated many times.

For example:

```text
amount = 6
```

can be reached through multiple paths.

This leads to exponential time complexity.

So plain recursion is not recommended.

---

# Approach 2: Recursion + Memoization

We define:

```text
f(amount)
```

as:

> Minimum number of coins needed to make the given amount.

For every coin:

```text
f(amount) = min(
    f(amount - coin) + 1
)
```

Base case:

```text
f(0) = 0
```

If:

```text
amount < 0
```

then the amount is impossible.

---

## Java Code

```java
class Solution {
    public int coinChange(int[] coins, int amount) {
        int[] dp = new int[amount + 1];

        Arrays.fill(dp, -1);

        return helper(coins, amount, dp);
    }

    private int helper(int[] coins, int amount, int[] dp) {
        if (amount == 0) {
            return 0;
        }

        if (amount < 0) {
            return Integer.MAX_VALUE;
        }

        if (dp[amount] != -1) {
            return dp[amount];
        }

        int minCoins = Integer.MAX_VALUE;

        for (int coin : coins) {
            int result = helper(coins, amount - coin, dp);

            if (result != Integer.MAX_VALUE) {
                minCoins = Math.min(minCoins, result + 1);
            }
        }

        return dp[amount] = minCoins;
    }
}
```

There is one final issue: if the amount is impossible, the function returns:

```text
Integer.MAX_VALUE
```

But the problem requires:

```text
-1
```

So we can modify the final return.

---

## Correct Memoization Code

```java
class Solution {
    public int coinChange(int[] coins, int amount) {
        int[] dp = new int[amount + 1];

        Arrays.fill(dp, -1);

        int result = helper(coins, amount, dp);

        return result == Integer.MAX_VALUE ? -1 : result;
    }

    private int helper(int[] coins, int amount, int[] dp) {
        if (amount == 0) {
            return 0;
        }

        if (amount < 0) {
            return Integer.MAX_VALUE;
        }

        if (dp[amount] != -1) {
            return dp[amount];
        }

        int minCoins = Integer.MAX_VALUE;

        for (int coin : coins) {
            int result = helper(coins, amount - coin, dp);

            if (result != Integer.MAX_VALUE) {
                minCoins = Math.min(minCoins, result + 1);
            }
        }

        return dp[amount] = minCoins;
    }
}
```

# Approach 3: Bottom-Up Tabulation

Instead of starting from the target amount and going backward, we calculate all amounts from:

```text
0 → amount
```

Define:

```text
dp[i]
```

as:

> Minimum number of coins needed to make amount `i`.

Base case:

```text
dp[0] = 0
```

For every amount `i`, try every coin.

If:

```text
i - coin >= 0
```

then:

```text
dp[i] = min(dp[i], dp[i - coin] + 1)
```

---

## Java Code

```java
class Solution {
    public int coinChange(int[] coins, int amount) {
        int[] dp = new int[amount + 1];

        Arrays.fill(dp, amount + 1);

        dp[0] = 0;

        for (int i = 1; i <= amount; i++) {
            for (int coin : coins) {
                if (i >= coin) {
                    dp[i] = Math.min(dp[i], dp[i - coin] + 1);
                }
            }
        }

        return dp[amount] == amount + 1 ? -1 : dp[amount];
    }
}
```

# Why Do We Initialize with `amount + 1`?

We need a value that represents:

```text
Impossible
```

We can use:

```java
amount + 1
```

because the maximum number of coins required, if coin `1` exists, is:

```text
amount
```

For example:

```text
amount = 11
```

The maximum useful answer is:

```text
11 coins
```

So:

```text
amount + 1 = 12
```

acts as infinity.

We initialize:

```java
Arrays.fill(dp, amount + 1);
```

Then:

```java
dp[0] = 0;
```

# Approach 4: Unbounded Knapsack — 2D DP

This problem can also be viewed as an **Unbounded Knapsack** problem.

Why?

Because every coin can be used unlimited times.

We can define:

```text
dp[i][j]
```

as:

> Minimum number of coins required using the first `i` coins to make amount `j`.

For every coin, we have two choices:

```text
Take the coin
Don't take the coin
```

If we take the coin, we stay at the same coin index because we can use the coin again.

---

## Java Code

```java
class Solution {
    public int coinChange(int[] coins, int amount) {
        int n = coins.length;

        int[][] dp = new int[n + 1][amount + 1];

        for (int j = 1; j <= amount; j++) {
            dp[0][j] = amount + 1;
        }

        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= amount; j++) {

                if (coins[i - 1] <= j) {
                    dp[i][j] = Math.min(
                        dp[i - 1][j],
                        dp[i][j - coins[i - 1]] + 1
                    );
                } else {
                    dp[i][j] = dp[i - 1][j];
                }
            }
        }

        return dp[n][amount] == amount + 1 ? -1 : dp[n][amount];
    }
}
```

The important difference from **0/1 Knapsack** is:

```java
dp[i][j - coins[i - 1]]
```

We stay in the same row `i` because the coin can be used again.

# Comparison

| Approach | Time | Space | Recommendation |
|---|---:|---:|---|
| Brute Force Recursion | Exponential | O(amount) | Not recommended |
| Memoization | O(amount × n) | O(amount) + recursion | Good |
| 2D Unbounded Knapsack | O(amount × n) | O(amount × n) | Good for understanding |
| 1D Tabulation | O(amount × n) | O(amount) | Best |

---

# Which Approach Is Better?

The **1D Bottom-Up DP** solution is the best choice.

Why?

We only need:

```text
dp[0 ... amount]
```

We don't need to remember which coins we have already used because coins can be used unlimited times.

The state is simply:

```text
dp[i] = minimum coins required to make amount i
```

The transition is:

```text
dp[i] = min(dp[i], dp[i - coin] + 1)
```

# Final Recommended Solution

```java
class Solution {
    public int coinChange(int[] coins, int amount) {
        int[] dp = new int[amount + 1];

        Arrays.fill(dp, amount + 1);

        dp[0] = 0;

        for (int i = 1; i <= amount; i++) {
            for (int coin : coins) {
                if (i >= coin) {
                    dp[i] = Math.min(dp[i], dp[i - coin] + 1);
                }
            }
        }

        return dp[amount] == amount + 1 ? -1 : dp[amount];
    }
}
```

**Time Complexity:** `O(amount × n)`  
**Space Complexity:** `O(amount)`

where `n` is the number of coins.

# Core Pattern to Remember

This is an **Unbounded Knapsack / Minimum DP** problem.

```text
dp[0] = 0

For every amount:
    Try every coin

    if amount >= coin:
        dp[amount] =
            min(
                dp[amount],
                dp[amount - coin] + 1
            )
```

Think:

```text
Current Amount
      ↓
Choose a Coin
      ↓
Remaining Amount
      ↓
Minimum Coins for Remaining Amount
      ↓
+ 1 for Current Coin
```

The most important line is:

```java
dp[i] = Math.min(dp[i], dp[i - coin] + 1);
```

This means:

> "If I use this coin, can I make the current amount using fewer coins?"

For LeetCode 322, remember:

```text
Unlimited coin usage
        ↓
Unbounded Knapsack
        ↓
1D DP
        ↓
Minimize number of coins
```
